## Root Cause Analysis

**Network restriction on molab.run:**
- cloudflared uses QUIC/HTTP2 for tunnel connections
- molab.run blocks outbound QUIC to Cloudflare edge
- Cloudflare API token only has DNS permissions, not Tunnel permissions
- Therefore: Cloudflare Tunnel approach won't work from molab.run

## Recommendations

### Strategy 1: SSHX-Based (✅ Recommended)
```
Module order: sshx (web terminal) → frp (reverse tunnel) → persistent URL via custom domain
```
- Use `sshx share` for web terminal (already working)
- Use `frp` client on molab connecting to external frp server
- Point domain CNAME to frp server

### Strategy 2: External Gateway (✅ Alternative)
```
Molab → AlwaysData (where cloudflared runs) → Cloudflare → Public URL
```
- Run cloudflared on AlwaysData (which works fine)
- Molab connects to AlwaysData as upstream
- Public URL goes through AlwaysData's cloudflared

### Strategy 3: Self-Hosted Tunnel Server
```
Molab → Own tunnel server (e.g., on Oracle Cloud Free) → Cloudflare → Public URL
```
- Deploy frp server on Oracle Cloud Free (always-on)
- Molab runs frp client connecting to it
- Oracle Cloud has working cloudflared
